# Por que este arquivo existe (2026-07-28): todos os requirements do projeto
# declaram FAIXAS (`>=2.16,<2.22`, `>=0.10`, ...). Duas builds em datas
# diferentes produziam ambientes diferentes — inaceitável para um experimento
# que vai a artigo. O `results.json` já grava as versões efetivas de cada run,
# mas isso documenta o passado; isto aqui reproduz o ambiente.
#
# Uso: os Dockerfiles definem `PIP_CONSTRAINT=/app/constraints.txt`, então todo
# `pip install` da imagem respeita estes pinos sem precisar de `-c` explícito.
# Localmente:  pip install -r requirements.txt -c constraints.txt
#
# ORIGEM: ambiente de referência validado em 2026-07-28 (Windows, Python
# 3.11.9) no qual o benchmark completo rodou nas 14 arquiteturas, o AST
# carregou os pesos AudioSet e os backbones WavLM/HuBERT foram portados do
# PyTorch com max|dif| ~1e-05 contra a referência.
#
# O QUE NÃO ESTÁ AQUI, DE PROPÓSITO:
#   - `tensorflow`  : difere por imagem (tensorflow-cpu x tensorflow[and-cuda]);
#   - `torch`       : difere por imagem (wheel CPU nas imagens Keras, que só
#                     LEEM state_dict, x wheel CUDA onde ele de fato treina);
#   - `nvidia-*`    : resolvidos pelos extras do TF/torch e ajustados nos
#                     Dockerfiles (ver o override de nvidia-cudnn-cu12).
